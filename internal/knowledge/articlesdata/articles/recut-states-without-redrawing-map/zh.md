# 不重画地图，重切州：引擎的硬约束和一条走得通的流程

## 目标与最终可观察结果

做完这一篇之后，在游戏里应该能看到三件事：

1. 你选定的一个战略区里，原版的州被你自己划分的州替代，边界落在原版省界上。
2. 主菜单地图正常加载，开局后 `error.log` 里没有本文列出的六种致命错误。
3. 沿海省份的港口位一个没丢，开局不闪退。

这条路线面向做**架空或历史转换 Mod** 的作者：把原版一千多个州推倒重来，换成自己时代的行政区划，但**不重画省份图**。

## 开始前需要什么

**先说这条路线和工作台的关系。** 工作台的「地块」页能改单个州的省份列表，能在地图上把一个省份从一个州挪到另一个州，导出前会拦下"一个省份属于两个州"这种会崩溃的错误。但它没有批量重切、没有战略区校验、没有编号连续性校验，也不会替你重写建筑表。本文讲的是纯脚本路线，文件要你自己生成，工具要你自己写；本文给的是判据和顺序，不是可以照抄的命令。

- 原版安装目录里的四样东西只读：`map/definition.csv`（省份类型）、`map/strategicregions/`（战略区）、`map/buildings.txt`（建筑表）、`provinces.bmp`（省份图，只用来算邻接）。
- 会用 `-debug` 参数启动游戏并读 `error.log`。没有这个参数，闪退时日志可能是空的。
- 建议先读州文件：归属、核心、省份和建筑各写在哪 (`state-file-basics`)。

## 涉及的对象与关系

| 对象 | 位置 | 在本例中的作用 |
| --- | --- | --- |
| 州文件 | `history/states/` | 你要生成的产物；覆盖原版用原版确切文件名 |
| 省份定义 | `map/definition.csv` | 只读；省份的类型和是否沿海全从这里来 |
| 战略区 | `map/strategicregions/` | 只读；切州的硬边界 |
| 建筑表 | `map/buildings.txt` | 必须跟着重写；第一列是州编号 |
| 国家历史 | `history/countries/` | 首都被抢时要改指 |
| 州名 | `localisation/` | 州名和地图标签是两个键 |

## 1. 先决定：不动省份图

省份是地图的最小单位，重画它意味着形状、邻接、地形、海岸线、河流、补给点、建筑位置全部要自己承担，而且互相纠缠。只重切州则完全不同：省份一个不动，你只是把它们**重新分组**。这样你白拿：

| 白拿的 | 说明 |
| --- | --- |
| 省份邻接 | 谁挨着谁，引擎已经算好 |
| 地形与加成 | 山地、丘陵、平原、城市 |
| 海岸线与港口位坐标 | 港位在建筑表里，位置不用管 |
| 河流与渡口 | 过河惩罚 |
| 胜利点的位置 | 名字可以改，位置不用管 |

代价只有一个：州界只能落在原版省界上。原版在人口稠密区的省份密度约合几十公里一格，足够表达绝大多数历史区划。以东亚为例，原版 1172 个省份只切成 109 个州，平均近 11 省一州，原版把它切得粗是因为 1936 年的东亚不重要，不是因为省份不够。

**以下全是"不动省份图"这条路。**

## 2. 五条硬约束，按危险程度排

每一条都对应一次真实的加载失败或闪退。

### 2.1 州编号必须从 1 连续到最大值

引擎从 1 遍历到最大编号，缺一个就报 `Missing State ID`，然后主菜单判定**地图加载失败**，进不了单人游戏。我们实测新建 1083 跳过 1082 就进不去，改成 1082 恢复。

推论：**你不能随手抛弃原版编号**。如果你的切法把某个原版州的省份全部吃光，那个编号就悬空了，必须由你的某个新州**认领**它：用原版那个文件名输出你的州。原版文件名不全是"编号-州名"，要从磁盘上列目录取。

### 2.2 一个州的所有省份必须同属一个战略区

违反时主菜单地图加载失败，日志里把两个战略区的名字都写出来：

```
MAP_ERROR: State "..."(#1082) has provinces (#13375, #3305) belonging to different strategic areas: "..." (#5), "..." (#275)
```

原版有 304 个战略区文件。这条约束支配整个批次规划：**先按战略区切块，再在块内按你的行政区划分组**。现代的战略区和你的时代的地理对不上，这是必须接受的；某个历史上非进不可的核心区可能和一大片不相干的地方同属一区，那你只有两个选择：整区吃满，或整区不动。

### 2.3 一个省份只能属于一个州

违反时启动崩溃。重新编号后残留的旧文件仍然声明它的省份，是这条最常见的来源，所以生成州文件前先清空输出目录。

### 2.4 建筑表以州编号为键，切州后必须重写

一句话：丢掉一条港口位 = 某个沿海省没有港位 = 引擎警告"很可能崩"。第五节专门讲。

### 2.5 复用被吃空的原版编号，可能抢走原版国家的首都

原版某国的首都指向州 N，你把 N 的省份全吃了并用它承载自己的州，那个国家的首都就变成了它不拥有的州：

```
Attempting to set capital state #N for ..., they dont own it!
```

我们实测引擎拒绝设置并回落，不崩；另一位全面转换 Mod 作者的项目里有一次直接闪退。不要赌，一律修：扫一遍原版 `history/countries/`，把首都落在你已占用州上的国家改指到它仍拥有的某个州。

### 另外三条不致命但会让你查很久的

- **湖泊也是州的成员。** 原版 13414 个省份里陆地 10155、湖泊 126、海洋 3133。切州时按"排除海洋"筛，不要按"只要陆地"筛，否则湖留在原来的州里，游戏里就是自家境内一块别人的水域。
- **`.txt` 不能带 BOM，本地化 `.yml` 必须带。** 带了 BOM 的州文件整份作废，报 `Unexpected token: ï»¿state`，连锁到 2.1。
- **`buildings.txt` 结尾不能多一个换行。** 原版这个文件最后一行没有换行符。

## 3. 数据模型：两张手工维护的表

所有工具都从这两张表出发，它们是唯一的事实来源。

**表一：省份到州**，一行一个省份，同一个州的行里名字和归属冗余填写，方便肉眼扫：

```
province_id,state_key,name_zh,name_en,owner
7656,my_capital_prefecture,开封府,Kaifeng,MYT
4066,my_capital_prefecture,开封府,Kaifeng,MYT
```

**表二：州的属性**，一行一个州：

```
state_key,state_id,override_file,category,manpower,vp_province,vp_value,infrastructure
my_capital_prefecture,1098,,metropolis,2000000,7656,30,4
my_border_prefecture,615,615-Shanxi.txt,town,300000,1531,2,2
```

`override_file` 非空时，用这个原版文件名输出，这就是 2.1 里"认领悬空编号"的实现。`vp_province` 必须真属于该州。

除此之外从原版一次性合成三份只读索引：省份总表（类型、是否沿海、地形、质心、原版所属州）、省份邻接（从省份图逐像素扫，存颜色而不是编号）、省份到战略区。像素级扫描用编译型语言做，纯脚本循环一千多万像素要几分钟。

## 4. 一个批次的流程

```
① 勘察     按战略区列出候选省份、城市锚点、原版州归属
② 画映射   手写上面两张表                        ← 唯一需要人的一步
③ 校验     连通性 / 同战略区 / 省份被两批重复认领 / 两表键 1:1
④ 查洞     被你的领土完全包围的空缺（含湖）
⑤ 出州文件 生成 history/states/*.txt 和州名本地化
⑥ 出覆盖   削减被削的原版州 / 报被吃空的编号 / 校验编号连续
⑦ 修首都   原版国家首都被抢时改指
⑧ 修建筑   重写 buildings.txt，见第五节
⑨ 装机     开 -debug 跑，读 error.log，有残留回 ⑧
```

①到⑧全程不启动游戏。⑨是整条流水线里唯一需要人坐在电脑前的步骤，省着用。

**勘察时就要做预检**：本区涉及哪些原版州，哪些整块在内（吃光就得认领它的编号）、哪些横跨到区外（会变成一个被削减的原版州）；区内有没有湖；有多少沿海省。当一个战略区恰好等于若干完整原版州的并集时，这一批会异常干净。

**查洞用连通分量，不用逐省评分。** "洞"是连通分量的性质，不是单个省份的性质：取所有未被认领的非海洋省份，求连通分量，最大的那个是外部世界，排除掉，剩下每一个都是被你包围的洞。逐省评分永远发现不了多省连成的洞。

**两张图都要看**：按你的表渲染的切州图看形状；按合并后的 `history/states/` 渲染的归属图看最终归属，后者才和游戏同源。

## 5. 建筑表：让引擎当权威

这是整套方法里最反直觉的一章。**先说结论：不要试图模拟引擎，引擎会把答案直接打印给你。**

### 5.1 问题

`map/buildings.txt` 六万多行，第一列是州编号：

```
state;type;x;y;z;rot;sea_province
598;naval_base_spawn;4666.96;9.50;1228.61;-4.07;2757
```

引擎从坐标反查省份，再校验这个省份是不是真在声明的州里。对不上就丢弃该行。我们实测把一个省份从州 8 挪到州 1082 后，指向它的十二行全部被丢，日志是这样的：

```
map/buildings.txt error at line 50927: map building(民用工厂) location is not within specified state. Supposed to be '8 - ...' but was '1082 - ...'for province 13375. BUILDING IGNORED!
```

丢掉的如果是港口位，引擎接着报"该省设为沿海但没有港口建筑，很可能崩溃"。另一位作者的项目里这一条对应真实闪退；我们只实测了内陆省份，没崩。

### 5.2 错误的做法：采样像素模拟引擎

最自然的想法是"引擎从坐标反查省份，我也用同样的方式采样省份图"。另一位作者的实测证明这条路会造成两类损坏：州界附近差一个像素就取到邻州，脚本无条件覆写，某一轮一百多条被丢弃的行**全部**是脚本改坏的；港口坐标在水边，采样常落在海洋省份上，海洋没有州，于是被归进"无法解析"原样保留，而那恰恰是会崩的那一行。

### 5.3 正确的做法

**铁律一：采样出的省份不在你的切州范围内，就一个字节都不动。** 不在范围内说明原版本来就是对的。

**铁律二：港口不靠像素定位。** 每行最后一个字段是港口通向的海洋省份，陆地省必然是它的邻居之一，取离坐标最近的那个，用真实邻接算。

**铁律三：边界未动的州，原版的键仍然权威。** 你的某个州认领了原版编号且省份集合与原版完全相同，原版指向它的行必然仍然成立，重算只可能把对的改错。这条可以直接做成事前关卡：逐行比对原版与你的输出，凡是指向"边界未动的州"的行被改了，就是回归。

**铁律四：引擎报错里的答案拆成两半，只存不变的那一半。** 上面那行报错里，"行号到省份"是地图的属性，你怎么切州都不变，存下来永久有效；"省份到州"由你当前的切法决定，每次重算。这样历史日志在你重新切州之后依然有效，跨批次累积，越跑越准。

### 5.4 每州定额的十类建筑位

原版对十类建筑位是每州固定行数，全表总行数正好是 1081 的整数倍：

| 类型 | 每州行数 |
| --- | --- |
| 机场、火箭基地、要塞网、合成炼油厂、核反应堆、雷达站、燃料库 | 1 |
| 军用工厂、民用工厂 | 6 |
| 防空阵地 | 3 |

重切会打乱这个分布，有的州拿到三个机场位，有的一个没有。缺了的州引擎报 `MAP_ERROR: no air base site defined for state N`。我们实测两个州各缺一行，报错但没崩；另一位作者的项目里几十个州成批缺失时伴随闪退，而且后三类缺失时**引擎一个字都不写日志**，点开始游戏当场死。稳妥做法是按原版定额补齐：把多出来的整行搬到缺的州去，**州键和坐标一起改**，坐标必须落在目标州境内，否则引擎判"不在指定州内"直接忽略，等于没搬。

### 5.5 港位不等于港口

上面这一整套只保证港口**位**的州键正确。港口**建筑**要写在州文件的 `buildings` 块里，按省份编号：

```
buildings = {
    6583 = {
        naval_base = 1
    }
}
```

两件事分开做。

### 5.6 闭环

```
开 -debug 跑 → 读 error.log → 贴回引擎给的真值 → 装机 → 再跑
```

一到两轮收敛。行号始终稳定，因为所有处理都只改第一列，从不增删或重排行。**验证前不要清 `error.log`**，清了就去崩溃目录里的日志快照捞。

## 6. 逐项核对

每一批收尾按这个表过一遍，前七项不用启动游戏：

| 检查 | 期望 |
| --- | --- |
| 两张表的键 1:1 对上，编号与覆盖文件名唯一 | 通过 |
| 没有省份被两个批次同时认领 | 通过 |
| 每个州内部连通（岛屿等已知例外显式标注） | 通过 |
| 每个州的省份同属一个战略区 | 通过 |
| 州编号 1 到最大值无空洞 | 通过 |
| 被完全吃空的原版州全部已被认领 | 通过 |
| 没有飞地，或飞地是有意为之 | 通过 |
| 归属图上每块地归对了国 | 肉眼 |
| 开 `-debug` 启动，六个致命模式全为零 | 见下 |

六个致命模式：`BUILDING IGNORED`、`no port building in the nudger`、`Missing State ID`、`provinces belonging to different strategic areas`、`dont own it`、`invalid province building`。

崩溃时四个地方都要看：`logs/error.log` 看原因；`logs/game.log` 看最后跑到哪一步，正常收尾会有"Launching SINGLEPLAYER-game"之后的渲染设备恢复日志；`crashes/<最新>/exception.txt` 看异常地址，**地址相同等于同一个 bug**；`crashes/<最新>/logs/error.log` 是崩溃瞬间的快照。

## 常见错误

- **用采样像素模拟引擎的省份解析**：引擎自己会把答案印在报错里，模拟它既不必要也不可靠。
- **用逐省评分找洞**：多省连成的洞永远发现不了，用连通分量。
- **三个检查脚本都写"只要陆地"**：同一个错误假设复制三遍，三层检查有同一个盲区（湖）。冗余检查只有在假设不同的时候才是冗余的。
- **按关键词认错误**：`MAP_ERROR` 这个前缀既出现在致命的战略区冲突里，也出现在大量无害的噪音里（你的时代不该有的机场位缺失会占日志九成）。建一份自己的良性噪音清单，每次只查六个致命模式是否为零。
- **没开 `-debug` 就查崩溃**：普通模式下 `error.log` 可能是空的。
- **一次改多个变量**：崩溃排查的效率完全取决于一次只动一个。

## 想改成别的做法？

- **不可操控的邻国按原版州 1:1 沿用**：剩余的战略区往往只含完整的原版州，整个收编，连通性和跨区约束结构上不可能出错，编号天然 1:1。这是覆盖"世界其余部分"的主力手段，但它省掉的是逐省考据，没省掉"这块地归谁"的考证。
- **拆一个跨了真实边界的原版州**：一半用原版文件名认领原版编号，另一半接在最大编号后面开新编号。不破坏任何硬约束。
- **只想改造型不改玩法**：见把一张参考图切成地块 (`reference-image-to-states`)。
