# 把一张参考图切成地块：总统山

## 目标与最终可观察结果

做完这一篇之后，在游戏里应该能看到：拉远镜头看美国本土，政治地图上的国界拼出一张可辨识的图。原始案例是拉什莫尔山的四张总统脸：本土 42 个州、810 个省份重新分组，世界其余部分一个字节不动。

这是一个纯造型练习，不是史实或平衡改动。它有价值是因为它把重切州 (`recut-states-without-redrawing-map`)那条路线推到了极端，撞出来的上限和坑对任何想在地图上"画"东西的人都适用。

## 开始前需要什么

- 读完不重画地图，重切州 (`recut-states-without-redrawing-map`)，本文引用它的五条硬约束和建筑表那一节，不重复。
- 这条路线在工作台里没有落点，文件要自己生成。本文讲的是判据，不是命令。
- 一张参考图，规格见第二节。
- 会用 `-debug` 启动游戏并读 `error.log` 和 `game.log`。

## 涉及的对象与关系

| 对象 | 在本例中的作用 |
| --- | --- |
| 参考图 | 量化成 2 到 4 档，每个省份按多数票定档 |
| 州文件 | 42 个，全部沿用原版文件名，只改省份分组和归属 |
| 国家 | 每档一个国家，靠拥有国上色 |
| `common/countries/colors.txt` | 国家颜色真正生效的地方 |
| `common/defines/` | 让国家色填满州内部的一个覆盖值 |
| `map/buildings.txt` | 州键跟着重切走，每州定额要补齐 |

## 1. 三个必须先接受的物理上限

这三条是原作者实测出来的，画什么之前先拿它们筛一遍。

**分辨率天花板约 50 乘 25 格。** 美国本土可用省份 810 个，包围盒约 887 乘 428 像素，省份平均边长约 17 像素。省份大小东西不均，西部约 23 像素一省，东部约 12 像素，所以画面右侧能承载的细节大约是左侧的两倍：主体特征往东放，大色块往西放。

**任何可辨识特征至少两格。** 也就是至少画布宽度的二十五分之一。低于这个，多数票会把它整个吃掉，不是变模糊，是直接消失。实测：横条纹、粗体块状字母、加粗的五角星、卡通比例的笑脸能活；尖角五角星、侧脸剪影、雄鹰羽毛、写实肖像全糊。

**画布是 2.07 比 1 的扁框。** 单张写实肖像做不出来：拉伸铺满脸被抻成香肠，保持比例脸只占中间一半宽度，五官掉到一格以下。唯一能活的人脸是表情符号比例的卡通脸，大脸、粗轮廓、五官夸张到各占两格以上，铺满整幅，靠色块不靠线条。

## 2. 参考图规范与州预算

| 项 | 规定 |
| --- | --- |
| 长宽比 | 越接近 2.07 比 1 越好 |
| 颜色数 | 2 到 4 种，3 是甜点 |
| 上色方式 | 纯色平涂，不要渐变、抗锯齿、纹理、阴影 |
| 色差 | 任意两色距离要大，参考图的颜色只用来分档，不会被搬进游戏 |
| 构图 | 铺满整幅，不留白边，白边会被当成一种主色 |
| 线条 | 不要描边，描边是第三种颜色而且必然细于两格 |
| 格式 | 无损 PNG，JPG 的块效应会造出一堆伪主色 |

**州预算是 42。** 本土原版有 42 个州，重切后的州数等于"档数乘以战略区数"里实际出现的组合数。本土跨 11 个战略区，一个州的省份必须同战略区，所以 N 档最坏要 11 乘 N 个州：3 档最坏 33，安全；4 档最坏 44，可能超。实际值取决于图案怎么落在战略区上，必须先算再动手。分出来不够 42 组时，把最大的组按长边一分为二：同档同战略区，画面完全不变，只多一条州界。

## 3. 定档用多数票，不用平均值

按面积平均降采样，跨边界的省份会被算成中间值，每条硬边上都长出一圈假的过渡色，轮廓就没了。改成"省内哪一档像素最多就归哪档"，硬边就保住了。灰度分档同样不行，六档灰度的第一版八成省份落进相邻两档，整幅糊成中灰。

## 4. 上色：每档一个国家，颜色不能照抄

政治地图按**拥有国**上色，所以要在游戏里看见明暗，每档必须归**不同的国家**。只切边界不换归属，游戏里跟没切一样。

**颜色不能照抄参考图。** 引擎画政治地图时把国家色和地形混在一起：大色块中心只有约三分之一是国家色，其余是地形透出来的；地形自身的亮度变化比两国之间的亮度差还大，所以只靠亮度分档一定糊；色相保留，饱和度砍到六成，整体压暗。结论是必须按**色相**分档，而且可用色相只剩青到品红这一段：红撞加拿大，橙到橄榄是地形自己的色相带，绿撞墨西哥。

原作者实测的三档调色板：暗档帝王紫 `118 13 127`，中档钴蓝 `64 96 255`，亮档青 `0 255 255`；按参考图各档的亮度排序映射，画面的明暗结构才不会被打乱。两档时取分得最开的一对（紫和青），不要顺序取前两个。

**改颜色要改 `common/countries/colors.txt`，不是国家文件。** `colors.txt` 会覆盖 `common/countries/<TAG>.txt` 里的 `color`，改后者完全无效。

**让国家色填满州内部。** 图形定义里有一个覆盖值，默认为零表示禁用：

```
NDefines_Graphics.NGraphics.GRADIENT_BORDERS_CAMERA_DISTANCE_OVERRIDE_COUNTRY = 0.05
```

写进 `common/defines/` 下一个自己的文件，这个文件只写 ASCII 注释。看图的镜头高度在 500 到 900 之间最合适：州界已经淡掉，国界还在，整个本土进得了屏。

**用来上色的国家借原版标签，不要自造。** 换成全新标签后，主菜单进得去，一点开始游戏就当场死，不写任何日志。借三个开局不拥有领土的原版标签，它们自带全套支持文件和三个尺寸的合法旗帜。

## 5. 建筑表：每州定额要补齐

重切后建筑表的州键跟着省份走，位置不动，于是有的州一行都分不到。原版对十类建筑位是每州固定行数（七类各 1 行，两类工厂各 6 行，防空 3 行，全表正好是州数的整数倍）。原作者的实测：先只补了每州 1 行的七类，理由是"另外三类引擎不报错"，结果 MAP_ERROR 确实没了，但点开始游戏仍然当场死，而且一个字都不写日志。**不报错不等于没事。** 十类一起按原版定额补齐，修法是整行搬迁，州键和坐标一起改，坐标必须落在目标州境内。

## 6. 逐项核对

| 检查 | 期望 |
| --- | --- |
| 42 个州文件全部沿用原版确切文件名 | 通过 |
| 编号 1 到最大值无空洞，无空州，无重复省份，无丢失省份 | 通过 |
| 每个州不跨战略区，无海洋省份 | 通过 |
| 每档对应一个不同的拥有国，美国首都所在的州归美国 | 通过 |
| 每个国家有明确领袖 | 通过 |
| `.txt` 不带 BOM，`.yml` 带 BOM，建筑表结尾无换行 | 通过 |
| 港口行数等于沿海省数；十类建筑位每州定额与原版一致 | 通过 |
| 建筑表所有坐标字段匹配纯数字格式 | 通过，见常见错误第一条 |
| 开 `-debug` 启动，进主菜单、能点开始游戏 | 肉眼 |

所有检查都从**写出来的文件**重新读，不信内存里的中间结果。

## 常见错误

- 🔴 **写进游戏文件的数字带了千位分隔符**：区域设置会把 1428.5 写成 1,428.50，引擎解析不出位置，整行判"不在陆地上"丢掉。这条错误只在点开始游戏时才打印，原作者三轮没查到。写完拿纯数字格式的正则把所有数字字段验一遍。
- 🔴 **自制旗帜贴图**：主菜单崩溃，异常类型在两种之间随机切换，这是内存被写坏的特征，读日志永远定位不到。文件头和原版逐字节相同也照崩。借原版标签，不生成旗帜。
- **只补七类建筑位**：见第五节，不报错不等于没事。
- **美国首都所在的州没归美国**：引擎报首都不归自己，先查那个州落在哪一档，那一档归美国。
- **只改边界不改归属**：游戏里看不出切过。
- **改国家文件里的颜色**：无效，改 `colors.txt`。
- **从参考图按频次取前几个主色**：抗锯齿产生的近似色频次比真正独立的颜色还高。取一个就把颜色距离近的全排除。

## 想改成别的做法？

- 想画国旗、大字母、简单几何图案：最稳，条纹每条 3 到 4 格。
- 想画人像：只有表情符号比例的卡通脸能活，写实不可能。
- 想在别的国家画：先算那个国家本土的省份数、包围盒和战略区数，三个上限全部要重算。
