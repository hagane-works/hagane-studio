# Turning a reference image into states: Mount Rushmore

## Goal and observable result

When this page is done you should see this in game: zoom out over the continental United States and the country borders on the political map spell out a recognisable picture. The original case is the four presidents of Mount Rushmore: 42 continental states and 810 provinces regrouped, with not a byte of the rest of the world touched.

It is a pure exercise in looks, not a historical or balance change. It is worth a page because it pushes the re-cutting states (`recut-states-without-redrawing-map`) route to its extreme, and the limits and traps it ran into apply to anyone who wants to "draw" on the map.

## What you need before starting

- Read re-cutting states without redrawing the map (`recut-states-without-redrawing-map`); this page refers to its five hard rules and its building-table section without repeating them.
- This route has no landing in the workbench; the files are generated by your own tooling. This page gives criteria, not commands.
- A reference image, to the spec in section two.
- The ability to launch with `-debug` and read `error.log` and `game.log`.

## Objects involved

| Object | Role in this example |
| --- | --- |
| Reference image | Quantised into 2 to 4 levels; each province takes the level of its majority vote |
| State files | 42 of them, all under their base-game filenames, with only provinces and owners changed |
| Countries | One per level; colouring comes from the owner |
| `common/countries/colors.txt` | Where country colours actually take effect |
| `common/defines/` | One override value that fills state interiors with country colour |
| `map/buildings.txt` | State keys follow the re-cut; per-state quotas must be restored |

## 1. Three physical limits to accept first

These three were measured by the original author; run any idea through them before drawing.

**The resolution ceiling is about 50 by 25 cells.** The continental United States has 810 usable provinces in a bounding box of about 887 by 428 pixels, so the average province is about 17 pixels across. Province size is uneven: about 23 pixels in the west and about 12 in the east, so the right side of the picture carries roughly twice the detail of the left. Put the main features east and the large colour blocks west.

**Any recognisable feature needs at least two cells.** That is at least one twenty-fifth of the canvas width. Below that, the majority vote swallows it whole; it does not blur, it disappears. Tested: horizontal stripes, bold block letters, a thickened five-pointed star and an emoji-proportioned cartoon face survive; a sharp-pointed star, a face silhouette, eagle feathers and a realistic portrait all smear.

**The canvas is a 2.07 to 1 letterbox.** A single realistic portrait cannot be done: stretched to fill, the face becomes a sausage; kept in proportion, it occupies only the middle half and the features drop below one cell. The only face that survives is an emoji-proportioned cartoon: big face, thick outline, features exaggerated to two cells or more each, filling the whole frame, built from colour blocks rather than lines.

## 2. Reference image spec and the state budget

| Item | Rule |
| --- | --- |
| Aspect ratio | As close to 2.07 to 1 as possible |
| Number of colours | 2 to 4; 3 is the sweet spot |
| Painting | Flat solid colours; no gradients, anti-aliasing, texture or shadow |
| Colour distance | Any two colours far apart; image colours are only used to assign levels and are never carried into the game |
| Composition | Fill the frame; no margin, since a margin counts as a colour |
| Lines | No outlines; an outline is a third colour and always thinner than two cells |
| Format | Lossless PNG; JPEG block artefacts create spurious dominant colours |

**The state budget is 42.** The continental United States has 42 base-game states; after the re-cut the number of states equals the number of "level times strategic region" combinations that actually occur. The mainland spans 11 strategic regions and a state's provinces must share one, so N levels need at worst 11 times N states: 3 levels is at worst 33, safe; 4 levels is at worst 44, possibly over. The real figure depends on how the picture falls across the regions; compute it before starting. When the grouping yields fewer than 42, split the largest group in two along its long axis: same level, same region, the picture is unchanged and there is merely one more border.

## 3. Assign levels by majority vote, not by averaging

Area-averaged downsampling turns every province on a border into an in-between value, so a ring of false transition colour grows along every hard edge and the outline is gone. "Whichever level has the most pixels inside the province wins" keeps the edges. Greyscale levels fail the same way: a first version with six grey levels put eight in ten provinces into two adjacent greys and the whole thing smeared into mid-grey.

## 4. Colouring: one country per level, and never copy the image's colours

The political map colours by **owner**, so to see light and dark in game each level must belong to a **different country**. Cutting borders without changing ownership looks in game as if nothing was cut.

**Colours cannot be copied from the image.** When drawing the political map the engine blends country colour into terrain: only about a third of a large block's interior is country colour, the rest is terrain showing through; the terrain's own brightness varies more than the brightness difference between two countries, so brightness-only levels always smear; hue is kept, saturation is cut to sixty percent, everything is darkened. The conclusion is to separate levels by **hue**, and the usable hues are only the cyan-to-magenta band: red clashes with Canada, orange through olive is the terrain's own hue band, green clashes with Mexico.

The original author's tested three-level palette: dark imperial purple `118 13 127`, mid cobalt `64 96 255`, light cyan `0 255 255`; map them in order of each level's brightness in the image, or the light-and-dark structure is scrambled. For two levels take the pair that is furthest apart (purple and cyan), not the first two in order.

**Change colours in `common/countries/colors.txt`, not in the country file.** `colors.txt` overrides the `color` in `common/countries/<TAG>.txt`; editing the latter does nothing at all.

**Fill state interiors with country colour.** The graphics defines contain an override value that defaults to zero, meaning disabled:

```
NDefines_Graphics.NGraphics.GRADIENT_BORDERS_CAMERA_DISTANCE_OVERRIDE_COUNTRY = 0.05
```

Put it in a file of your own under `common/defines/`, with ASCII-only comments. A camera height between 500 and 900 is the sweet spot for viewing: state borders have faded, country borders remain, and the whole mainland fits the screen.

**Borrow base-game tags for the colouring countries; do not invent new ones.** With brand-new tags the main menu loads, and the game dies the moment "start game" is pressed, writing no log at all. Borrow three base-game tags that own no land at start; they come with full supporting files and legal flags in all three sizes.

## 5. The building table: restore the per-state quotas

After the re-cut the building table's state keys follow the provinces while positions stay put, so some states get no lines at all. For ten types the base game has a fixed number of lines per state (seven types at 1 each, two factory types at 6, anti-air at 3, the table's totals being exact multiples of the state count). The original author's test: restoring only the seven 1-per-state types, on the reasoning that "the engine does not complain about the other three", made the MAP_ERROR lines disappear, yet "start game" still died on the spot, writing nothing to the log. **No error does not mean no problem.** Restore all ten to the base-game quota by moving whole lines, changing the state key and the coordinates together, with coordinates inside the target state.

## 6. Check each item

| Check | Expected |
| --- | --- |
| All 42 state files under their exact base-game filenames | Pass |
| Ids 1 to max with no gaps; no empty state; no duplicate or missing province | Pass |
| No state spans strategic regions; no sea province | Pass |
| Each level belongs to a different owner; the state holding the US capital belongs to the USA | Pass |
| Every country has an explicit leader | Pass |
| `.txt` without BOM, `.yml` with BOM, no trailing newline in the building table | Pass |
| Port site lines equal coastal provinces; the ten per-state quotas match the base game | Pass |
| Every coordinate field in the building table matches a plain-number pattern | Pass, see the first common mistake |
| Launch with `-debug`, reach the main menu, press start | By eye |

Every check reads the **written files**, never in-memory intermediates.

## Common mistakes

- 🔴 **A thousands separator in a number written to a game file**: a regional setting writes 1428.5 as 1,428.50, the engine cannot parse the position, and the whole line is dropped as "not over the land". This error is only printed when "start game" is pressed; the original author missed it for three rounds. After writing, validate every numeric field with a plain-number pattern.
- 🔴 **Home-made flag textures**: crashes at the main menu, with the exception type alternating between two kinds, the signature of memory corruption, which log reading never locates. Identical file headers to the base game byte for byte still crashed. Borrow base-game tags and generate no flags.
- **Restoring only seven building types**: see section five; no error does not mean no problem.
- **The state holding the US capital not owned by the USA**: the engine reports the capital is not owned; find which level that state falls in and give that level to the USA.
- **Changing borders without changing ownership**: in game it looks uncut.
- **Changing the colour in the country file**: no effect; change `colors.txt`.
- **Taking the top N most frequent colours from the image**: near-duplicates from anti-aliasing outrank genuinely distinct colours. Take one, then exclude everything close to it.

## Want a different approach?

- Flags, big letters, simple geometry: the most robust; stripes of 3 to 4 cells each.
- Portraits: only emoji-proportioned cartoon faces survive; realism is impossible.
- Another country: recompute all three limits from that country's mainland province count, bounding box and strategic region count.
