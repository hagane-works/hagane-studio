This four-step exercise defines a Research Training national spirit that provides Research Speed +5%, adds its English name, and gives you checks for the result.

The series teaches the game files themselves, without requiring a particular editor. You do not need to draw an icon, write an event or build a focus tree first.

## Create a separate local Mod

Use the game launcher's local Mod creation feature. You can name it “Hagane Works Learning Exercise” and use `hw_learning` for the content folder. Button positions vary between launcher versions; check the files it creates rather than relying on an old screenshot.

Use the `mod` folder in the game's user-data directory. Do not edit the game installation directly. If your Documents directory has been redirected, use the actual location of the game's user data.

This is the **expected structure after completing the first three steps**, not a script:

```text
mod/
├── hw_learning.mod
└── hw_learning/
    ├── descriptor.mod
    ├── common/
    │   └── ideas/
    │       └── hw_learning_ideas.txt
    └── localisation/
        └── english/
            └── hw_learning_l_english.yml
```

For now, check the two descriptor files. The next two steps add the script and localisation.

## What do the two descriptors do?

The external `hw_learning.mod` tells the launcher the Mod's name and where its content is. This is the **minimal local descriptor for the exercise**, provided for comparison. Keep other valid fields generated by your launcher.

```hoi4
name="Hagane Works Learning Exercise"
path="mod/hw_learning"
supported_version="1.19.*"
```

The `descriptor.mod` inside the content folder stores the Mod's own description. This is the **minimal internal descriptor for the exercise**:

```hoi4
name="Hagane Works Learning Exercise"
supported_version="1.19.*"
```

Neither file is where you define spirits or focuses. `path` must point to the actual content directory. If the launcher generates a different valid path for your location, keep it rather than blindly replacing it with this example.

`supported_version` declares a compatibility range. It does not update the game or prove that the Mod was tested on every version in that range. This series was checked against sources for 1.19.2.0.

## Keep scripts and display text separate

| File | Purpose | Encoding used in this series |
| --- | --- | --- |
| `.mod`, `descriptor.mod` | Tell the launcher how to load the Mod | UTF-8 without BOM |
| `common/ideas/*.txt` | Define spirits and their values | UTF-8 without BOM |
| `localisation/english/*_l_english.yml` | English in-game names and descriptions | UTF-8 with BOM |

The exercise uses its own filenames and an `HW_` ID prefix rather than copying an entire vanilla ideas file. This reduces accidental overrides, but your filenames and IDs must still be unique within the Mod.

Do not add `replace_path` to “force the Mod to load”. This exercise only adds its own content; it does not need to replace a whole vanilla directory.

## What should I check before moving on?

- The launcher finds the new local Mod and points to your `hw_learning` content folder.
- Real file extensions are visible. Neither descriptor is accidentally named `descriptor.mod.txt` or `hw_learning.mod.txt`.
- No vanilla files or existing Mods have been overwritten for this exercise.
